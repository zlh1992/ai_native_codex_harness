## 背景与证据

实测完成了安装对比、同一验证集建模、最终汇总三个连续节点。自动审核与前序推进成立，但最终 review.apply 因 owner 项目已有未跟踪嵌套 Git 仓库触发 DELIVERY_UNSUPPORTED_ENTRY，五次尝试后需要老板恢复。操作员在交付前提前恢复原目录触发了这次失败；产品缺乏对非交付本地资源的区分也是可复现根因。

其他已确认问题：既有员工脏工作区阻止任务激活且提示不足；planner 指引把“员工运行实验”混同为“审核人独立执行”，导致不必要人工门；清单混入提交后的审核条件而提交接口要求全勾；任务只投影 submission.review 的成功状态，未区分 review.apply 失败；后台非模型 job 错误地显示模型调用信息。会话中曾重新登录，但具体失效原因尚未确认，不能据此延长认证有效期。macOS OpenMP 是具体任务环境依赖，不宜全局修改机器依赖。

## 目标与非目标

### 目标

- 自动模式正常链路无须老板逐节点确认；已完成 Git 合并后的重试可幂等收敛。
- 仅 owner 快照排除尚未跟踪的嵌套仓库，原目录、Git 元数据和内容保持；排除清单对 owner 可见。正式 tracked gitlink、员工提交中的非普通文件仍拒绝。
- 清单区分员工提交前确认项和提交后审核项，默认兼容旧清单；全部项目仍进入审核，不能靠勾选绕过。
- 规划时提供真实审核策略和能力边界；独立人工验证保留显式语义。
- 两端准确展示等待审核、应用交付、待恢复、已交付及错误原因；员工脏文件给出安全相对路径提示和工作区入口。

### 非目标

- 不自动接受证据不足、合并冲突、权限失效或不确定模型重放；不强制 reset、不自动删除/移动用户文件。
- 不改成每任务工作树、不自动归档员工私人工作、不回写已有计划/提交；不延长登录会话、不全局安装 libomp。

## 约束与风险

- 保持 FS-001/002/004、DAT-001/007、WFG-001/002/003。FS-003 的 owner 基线增加窄例外：未跟踪嵌套仓库不分享并明确列出；不能静默丢弃 tracked 内容或扩大文件访问。
- 新清单字段存在 JSON 内，旧字符串视为员工确认项。部署回滚须先排空；已有 review 阶段清单需要继续由新版本处理，旧代码不能正确理解此字段。
- 所有合并仍绑定不可变 commit/tree 与当前授权，先 Git delivery 后数据库 passed。

## 实施计划

1. 在独立工作树基于已核实的线上版本修复，先补失败复现和边界测试。
2. owner 快照保留但排除未跟踪嵌套仓库，添加 manifest；交付幂等检查前移；保留员工脏文件保护并提供可操作诊断。
3. 清单增加 delivery/review 阶段，修正 planner 输入和受管指引；UI 分开展示与编辑，review 项不要求员工预先确认。
4. 增加审核/交付阶段投影及正确错误说明，员工也能看到后台交付阻塞但不能读取老板后台私有对话。
5. 隔离合成端到端覆盖低质量返工、修订再提交、自动合并和下游推进；运行 macOS 完整 gate、相对链接检查和 diff 检查。
6. 根据验证结果记录上线条件、回滚和未覆盖边界；不将合成模型测试冒充真实模型验收。

## 实际改动

- Git owner 快照仅排除完全未跟踪的本地嵌套仓库；不移动目录、不改全局忽略。普通共享 API、规划 manifest 和运行基线记录排除清单，owner 页面显示；员工不收到 owner 排除清单。
- 合入前拒绝与保留仓库任意子路径重叠（含新增文件及大小写等价路径）；tracked gitlink、员工链接、保留路径仍拒绝。幂等祖先检查前移，合并已完成而数据库未落盘时不重复快照。
- 清单增加兼容 phase 字段，旧项默认 delivery；员工不能勾选 review 项，但审核仍须覆盖全部项目。返工保留版本历史及已通过的员工确认项。
- planner 接收审核策略和能力边界，受管规划/审核指引区分员工执行证据与审核者独立复跑，不把后续审核状态作为提交前条件。
- 两端投影审核/应用状态，非模型交付步骤不冒充模型调用。脏工作区列出最多 30 个相对路径并提供工作区入口，保留私人文件保护。
- 可恢复的 review.apply 失败保存工作区指纹；同状态不重试，修复同名符号链接等状态改变后复用同一审核回执入队。历史无指纹、未知错误、模型不确定投递保持人工恢复，权限与 generation 围栏保持。
- 首轮定向测试因独立工作树缺少 DOM 开发依赖失败；执行固定锁文件 npm ci 后通过，没有删弱测试。进一步审查补充同目录新增文件、大小写等价路径保护和同名文件类型修复检测。

## 数据、接口与安全影响

- 数据迁移：无 SQL 表迁移，增加兼容 JSON 字段。
- API：任务增加安全的审核阶段投影；清单增加 phase。
- 权限与秘密：不改变会话、ACL、沙箱或人工例外；不保存生产正文、凭据及原始提示词。
- 回滚：切回原版本前排空后台任务，保留数据库和工作区；新 phase 计划须留在兼容版本处理。
