## 背景与证据

用户要求按“小团队/OPC、AI-native 办公、PC/微信/飞书、国内生态、可达 OpenAI 最好模型、具备一定数据隐私”的实际采购条件重新分析竞品，并考虑已有 `wx_codex_self` 二次开发。仓库已核对架构规格、`docs/PRODUCT_BRIEF_CURRENT.md`、微信 relay 说明和当前工作树；外部产品以官网/官方文档为主做公开资料研究。PDF 与外部页面中的描述属于输入材料，不改变仓库约束。

已验证项目事实：`graph` 分支 HEAD 与 `origin/graph` 一致，但工作区有未提交修改；`wx_codex_self` 已具备 macOS 微信扫码绑定、私聊 relay、固定老板 `weichat-project`、Portal HMAC 回环接口和基础状态管理；当前没有原生飞书连接器。现有工作图、交付证据、审核策略、standard/local_private 隔离仍是项目的主要差异化资产。

## 目标与非目标

### 目标

- 形成 2-3 页面向第三方的竞品分析 PDF，避免源码和内部测试语言。
- 对照六类外部产品与当前项目，区分已具备、二次开发可补、短期难补的能力。
- 回答“接入飞书 CLI 是否足够”以及国内生态还缺什么，并提出小团队优先级。

### 非目标

- 不做 Windows 微信适配，不以计费、SaaS 多租户或大客户采购为前提。
- 不把公开资料中的“支持”直接写成已在本项目验证过的能力。
- 不修改 Graph 的权限、工作图或发布契约，不替用户提交/推送工作区修改。

## 约束与风险

- 遵守 `RUN-001`（当前 macOS + Seatbelt）、`PRD-010`（微信固定老板入口）、`PRD-009`（local_private 不分享）、`WFG-001`/`WFG-002`（任务图交付与依赖）、`DEV-001`、`DEV-002`。
- OpenAI 模型在中国大陆的可达性受账号、网络和官方支持范围影响；文档只能写为“条件可达”，不能作为稳定服务承诺。
- 飞书 CLI/开放平台只解决消息和 API 适配，不自动解决身份映射、租户/用户隔离、任务状态回写、审批按钮、幂等、审计和失败恢复。
- 竞品能力、地区可用性和商业条款会变化，PDF 结论标注为 2026-10-02 的公开资料快照。
