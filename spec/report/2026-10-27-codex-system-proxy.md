## 背景与证据

生产元数据表明，员工失败请求实际选择 GPT-6.1 Sol，同期老板及另一条员工成功请求均使用 GPT-5.6 Sol。两角色共用 Codex 客户端，员工不是被角色 ACL 拒绝。账号额度查询显示周额度使用约 9%，未报告额度耗尽。

同一固定 CLI、同一登录和官方 provider 的隔离最小调用：原始子进程环境下 6.1 返回 429，5.6 返回完成；向隔离进程注入当前系统 HTTP/HTTPS 代理后，6.1 返回完成和文本回复。现有命令/浏览器已接入 OUTBOUND_PROXY，但 Codex 客户端仅继承宿主环境中的大写代理变量，后台启动没有这些变量，因而遗漏系统代理。429 具体由上游哪一层产生仍未知；不把它误报为账号额度耗尽或员工权限故障。

**首次上线后的反证**：代理环境修复已在生产进程生效，但老板选择 6.1 的临时验收仍返回 429；该临时项目和运维 session 已清理。因此初次隔离成功不足以证明代理是 429 的唯一根因，当时未声明恢复。相同账号的官方接口直接 HTTP 请求返回 completed 且响应 model 为 6.1；固定 CLI 请求（包含完整工具参数的独立最小探测）仍失败。临时、仅回环、仅转发官方接口的诊断观察不保存请求/凭据，只输出字段名称和状态；转发未经压缩的原生请求可成功。当时继续排查原生传输/请求压缩差异，未改变生产 provider 地址或账号。

**进一步版本对照**：关闭旧 CLI 请求压缩仍失败，单独改变 serviceName/工具注册也未恢复。相同官方 provider、登录、代理和显式模型下，本机 `0.164.0-alpha.11.1` 完成真实 6.1 调用，旧版仍 429。版本/传输兼容性是当前明确差异；上游具体拒绝原因未返回，不能声称已知道限流内部机制。按 PRO-001/002/003 扩展计划，保留老版本供回滚并升级精确 pin 与生成协议，完成完整 Portal 复验后才能宣布恢复。

## 目标与非目标

### 目标

- Codex 主进程及独立搜索客户端启动时使用现有 OUTBOUND_PROXY 解析器，统一 system / direct / 显式地址语义。
- 只传受控代理变量，拒绝继承冲突的宿主代理；错误不静默直连。
- 在 macOS 通过完整门控，排空/备份/发布后以真实双角色请求验收。

### 非目标

- 不改模型白名单、业务历史、员工权限和 Qwen 开关；不自动重放失败任务。CLI pin 因版本对照证据按协议升级流程调整，不放宽精确校验。
- 不引入代理转发服务或修改系统 VPN。长驻 Codex 进程启动后端口变化的热切换不在此次最小修复中；入口不变的节点切换由 VPN 处理，端口变化须排空后重启。

## 约束与风险

- 遵守 RUN-003/006、PRO-001/003、FS-006、DAT-003/006、DEV-001/003/004/006。
- 模型推理的服务级出站连接不等于员工工具的联网授权；禁网命令/浏览器仍拒绝本地代理。
- 代理不可达会使模型请求失败，不自动切换直连、模型或重放。系统配置读取失败在启动前明确失败。
- 重启前等待现有运行完成；保留 DB 和原 thread 映射。

## 实施计划

1. Codex 客户端启动前解析出站代理，移除任意环境代理继承，给最终子进程环境注入受控值。
2. 测试真实子进程收到系统/显式/direct 配置、重启读取新端口及错误时不启动；验证搜索客户端环境隔离仍有效。
3. 更新长期边界、操作指南和报告索引。
4. 完整 gate、diff 与相对链接检查；备份发布、双角色真实 GPT-6.1 Sol 冒烟及清理。
5. 若真实验收失败，记录反证并继续检查固定 CLI 的请求传输参数；不能以最小 HTTP 请求成功替代 Portal 验收。
6. 独立保存本机新 CLI 完整包；由该二进制生成协议（包含实际启用的 experimental API），核对原请求、通知、动态工具、原生记忆关闭、子代理和中断字段。更新 pin、夹具及版本契约，不删除原业务断言。
7. 重新执行完整 gate，先以隔离 Portal 验证新版与原工具链，再安全发布并完成双角色真实请求及原对话映射保留检查。
8. 升级安全核对发现宿主个人 MCP 配置仍可被原生 thread 继承；为保持第 04 章既有工具边界，在 start/resume/fork 的服务端配置中固定关闭宿主 MCP 条目及调用参数中新加的 MCP，保留 Portal dynamic tools。此防护不修改宿主个人配置。

## 实际改动

- `src/codex-client.mjs` 复用现有代理解析与环境生成；在主/搜索进程最终环境上注入，删除宿主代理变量继承。读取系统配置期间停止服务会取消启动，避免异步窗口遗留进程。
- `test/codex-client.test.mjs` 以真实 fake 子进程验证代理模式、端口更新、环境秘密/覆盖隔离、错误拒绝、搜索环境及启动取消；fixture 只增加测试查询与准确的搜索配置回显。
- 安全、发布、运维规格及执行指南注明服务级出站与工具权限的区别，以及模型进程端口更新须排空重启的限制。
- 版本对照后扩展为精确 CLI 升级：独立复制官方 App 的完整 `0.164.0-alpha.11.1` 包，生产使用 app bundle 内原生二进制；重新生成含 experimental API 的协议，更新 config、两个 fixture、版本测试与运维文档。新增 schema 字段不自动启用新权限。原 `thread/rollback` 从新 schema 移除，但 Portal 未使用；所有既有调用、动态工具、审批、通知、子代理及 steer 所需契约均保留并通过协议测试。安装默认入口同步到当前官方包布局。

## 数据、接口与安全影响

- 数据迁移：无。
- API/协议：Portal HTTP API 不变；原生 CLI 精确 pin 升级到 0.164.0-alpha.11.1，并由该版本完整重生成协议。四模型白名单保持。
- 权限与秘密：受控代理环境及 thread MCP 禁用；真实新版运行时验证宿主 MCP 状态为 disabled、tools/resources 均为空。未修改宿主个人配置，不输出凭据、业务正文或原始请求。
- 回滚：排空后恢复发布前代码及 CODEX_BIN 配置并重启，保留现有业务数据库。回滚会恢复本次代理遗漏。
