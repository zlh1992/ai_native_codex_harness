## 强制流程

1. 开始修改前，复制 [TEMPLATE.md](TEMPLATE.md) 创建 `YYYY-MM-DD-short-topic.md`。
2. 先填写背景、目标/非目标、影响分析和实施计划，并把状态设为“计划中”或“实施中”。
3. 实施期间记录实际决策、偏差、迁移和风险，不能只保留最初设想。
4. 完成后填写验证命令与结果、数据清理、回滚方式、结论和遗留事项，再把状态设为“完成”或“阻塞”。
5. 将新报告加入本索引。若改变长期架构、不变量、公开接口或 E2E 契约，同时更新 `spec/architecture/`。

同一业务目标的连续修复可以更新同一报告；不相关修改不得混在一个报告。报告中禁止写密码、token、Cookie、私有 key、完整 prompt、命令秘密或生产文件内容。

## 报告状态

- **计划中**：只有分析和计划，尚未修改。
- **实施中**：已有改动，但验证或结论尚未闭环。
- **完成**：计划范围已实现，验证通过，结论和遗留项完整。
- **阻塞**：无法继续，必须写清阻塞条件、已完成工作和恢复入口。
- **撤销**：决定不实施，必须说明原因和是否存在残留。
