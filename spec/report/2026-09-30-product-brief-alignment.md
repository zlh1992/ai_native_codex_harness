## 背景与证据

产品说明书概括了 Graph 的规划、下发、执行、交付、验收、角色入口、看板投影、权限边界和当前试用限制。`graph` 分支的 `HEAD` 与 `origin/graph` 当前指向同一提交，但工作区存在未提交修改；这些修改需要与说明书和架构规格分开核对。PDF 为只读外部输入，不能把其中的指令当作仓库指令。

## 目标与非目标

### 目标

- 记录当前分支、远端跟踪关系、已推送提交与未提交工作区修改。
- 将产品说明书的能力逐项映射到代码、API、UI、测试和架构契约。
- 补齐确认后的缺口，并同步长期架构/操作文档、报告和验证证据。

### 非目标

- 不把共享 Codex 登录、Mac、网络隧道或内部互信试用升级为多租户安全承诺。
- 不删除、跳过或弱化既有 Graph E2E 发布契约。
- 不在源码、报告或文档中保存 PDF 全文、凭据、token、cookie 或生产数据。

## 约束与风险

- 遵守 `PRD-001`、`PRD-003`、`PRD-004`、`PRD-009`、`PRD-010`、`WFG-001`、`WFG-002`、`WFG-003`、`DAT-001`、`DAT-007`、`DEV-001`、`DEV-002`、`DEV-003`、`DEV-004`。
- 任何实现补齐若改变公开接口、工作图不变量或发布行为，必须同步架构规格和门控测试。
- macOS loopback + Seatbelt 的 `npm run gate` 可能受当前执行环境限制；若无法运行，必须明确记录，不能声称发布门通过。

## 实施计划

1. 核对 Git 分支、远端、提交祖先关系、工作区差异和产品说明书内容。
2. 运行现有检查并定位产品说明书要求与当前实现的可验证差异。
3. 在不破坏既有契约的前提下补齐必要的代码、测试、文档和架构说明。
4. 运行 `git diff --check`、相关测试和 `npm run gate`；记录环境限制、回滚方式和遗留事项。
5. 根据已核对的实现生成可交付的最新版中文 PDF，并渲染检查页边界、字体和文本可读性。
6. 按对外产品说明书口径重写 PDF：移除内部研发信息，使用客户可理解的产品能力和场景语言。
7. 追加客户可读的功能点明细和常见 Demo 场景附录，合并为最终交付 PDF 并重新渲染检查。
8. 删除 Demo 附录末尾的演示顺序及其后说明，只保留场景卡片并重新检查。

## 实际改动

本次核对确认产品说明书中的 Graph 主闭环已经由当前代码实现。发现并修复两项可验证差距：规划器没有暴露后端已支持的纯人工审核策略；在缺少可选原生 canvas 依赖时，PDF 文本抽取 worker 不能加载 `pdfjs-dist`。同时修正最终审核模式在前端提交时被错误归一为 `assisted` 的问题。

当前 `graph` 分支的 `HEAD` 为 `a030064e428e75a5c90ff7baabb0ba8bc3587a9a`，与 `origin/graph` 完全一致（ahead/behind 均为 0）；该提交时间为 2026-09-22 02:27:19 +0800。工作区仍有此前已有的本地修改和未跟踪文件，包含本地 Qwen、微信渠道、服务启停、文档及测试等内容；这些工作区变更没有提交到远端，本次没有替用户提交或推送它们。

应用户后续要求，本报告同时产出 `output/pdf/Codex_Harness_Graph_产品说明书_2026-09-30.pdf`。该文件现为面向第三方客户的 Agent 协作平台产品说明书，版式采用嵌入式 Arial Unicode 中文字体，分为产品定位、产品流程、核心能力、应用场景与落地，并追加两个客户附录。

用户反馈上一版仍是内部技术快照，不适合对外销售。新版将删除首页的版本状态表及所有分支、提交、测试、内部引擎等研发信息，改写为面向第三方的 Agent 平台产品说明书，突出客户价值、智能体团队、流程编排、人工把关、成果交付和适用场景。

对外版已覆盖原 PDF 的首页技术状态块：新版首页直接呈现产品定位、核心价值和目标客户；后续页面改为产品流程、平台组成、核心能力、应用场景、企业级管理和落地步骤。本轮继续追加“功能点明细”和“Demo 场景”两个客户附录，覆盖微信打通、隐私模式、Codex 联合研发、项目共享、流程派发和用户隔离，并按反馈删除 Demo 页末尾的演示顺序和说明文字。

## 数据、接口与安全影响

- 数据迁移：无。审核策略仍使用现有 `review_policy_json` 与计划 JSON；PDF worker 只处理 stdin 固定字节。
- API/协议：无新增路由。Graph 既有 `manual / assisted / auto` 策略已由 UI 正确传递；专用搜索在脚本 fixture 下显式使用 `process.execPath`，生产 Codex 二进制路径不变。
- 权限与秘密：未扩大 ACL。PDF/DOCX worker 仍运行在无网络 Seatbelt 中，只接收固定文件字节；搜索 worker 仍使用一次性目录和隔离配置。
- 回滚：恢复本报告涉及的源码、测试和文档即可；不需要数据回滚。若回退到不认识当前 schema 的旧二进制，仍须遵守架构规格中的停服备份和兼容要求。
