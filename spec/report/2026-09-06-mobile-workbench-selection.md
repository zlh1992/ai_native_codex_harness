## 背景与证据

用户提供的手机截图显示，工作台在窄屏下把项目与对话侧栏压缩在很小的固定高度内；项目卡片被截断，对话列表只剩很窄的一条区域，无法稳定点选。代码检查确认 `public/styles.css` 的移动端规则同时设置了 `.project-rail{min-height:240px;max-height:40vh}`，而侧栏默认 `overflow:hidden`，使项目列表、空间卡片、对话标题和对话列表争抢同一段有限高度。老板 `/boss/workbench` 与员工工作台 `/employee` 共用该工作台页面与样式，因此两端均受影响。

## 目标与非目标

### 目标

- 在手机窄屏下移除侧栏整体的 `40vh` 截断，让项目区与对话区各自拥有清晰、可滚动的选择空间。
- 放大项目、对话条目及新增按钮的触控目标和文字，提升点选准确度。
- 保持桌面工作台布局与老板/员工服务端权限行为不变。
- 增加前端回归测试，防止重新引入小高度和窄触控目标。
- 验证后重启本地 Portal 与公网隧道，并确认角色入口可访问。

### 非目标

- 不改变项目、对话、模型、模式或消息队列 API。
- 不改变桌面端可调整侧栏布局。
- 不修改老板与员工的认证、ACL 或共享语义。

## 约束与风险

- 遵守 `spec/architecture/02-project-constraints.md`；本次不触及其中的权限、运行、数据与协议约束。
- 窄屏页面会比原先更长，用户需要向下滚动进入消息区；这是为确保两个选择列表拥有可靠触控空间而接受的移动端取舍。
- 应限制列表自身高度并启用滚动，避免项目或对话数量很多时无限推低消息区。
- 工作树已有其他未提交改动，本次仅追加聚焦的 CSS、测试和报告内容，不覆盖无关修改。

## 实施计划

1. 为窄屏工作台增加独立的项目/对话列表高度、滚动和触控尺寸规则。
2. 在 `test/frontend.test.mjs` 增加静态回归断言，锁定移动端不再使用 `40vh` 截断并保证至少 48px 触控目标。
3. 运行前端测试、完整 `npm run gate`、`git diff --check` 和 Markdown 相对链接校验。
4. 用移动视口渲染工作台进行视觉检查，必要时迭代。
5. 完成报告与索引，重启本地服务和公网隧道，确认 health 与老板/员工入口地址。

## 实际改动

- `public/styles.css`：在 `max-width:720px` 下取消项目/对话侧栏的 `40vh` 整体上限和隐藏裁切；项目列表与对话列表改成各自独立滚动区，最小高度分别为 156px 与 192px，并限制最大高度，避免大量条目无限推低消息区。
- `public/styles.css`：移动端项目/对话条目最小高度增至 64px，标题与辅助文字增大；新增项目/对话按钮增至 48×48px，并启用直接触控操作。
- `test/frontend.test.mjs`：新增移动端选择区回归断言，覆盖侧栏不裁切、双列表独立滚动、列表高度、条目高度和新增按钮尺寸。
- `spec/report/index.md`：登记本报告。
- 实施与计划一致；未修改桌面布局、服务端接口或架构规格。
