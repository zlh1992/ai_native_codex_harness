# Codex Harness Remote 规格入口

本目录是项目架构、约束和变更证据的规范入口。`docs/` 继续承载面向操作者的使用说明；`spec/` 负责回答“系统为什么这样设计、哪些条件必须保持、一次修改实际改变了什么”。

## 目录

- [架构规格](architecture/index.md)：当前架构、强制不变量、安全边界、运行时语义、恢复模型、端到端发布契约和演进边界。
- [实施报告](report/index.md)：每次仓库修改的实施计划、实际改动、验证结果、结论和遗留事项。
- [报告模板](report/TEMPLATE.md)：新变更报告的最低内容要求。

## 事实优先级

出现冲突时按以下顺序处理，不得用过期文档覆盖运行事实：

1. 数据库约束、安全检查和当前可执行代码；
2. 自动化测试，特别是 `npm run gate` 中的端到端发布契约；
3. `spec/architecture/` 中的规范性不变量；
4. `spec/report/` 中带日期的实现快照；
5. `README.md` 与 `docs/` 中的操作说明。

发现冲突不表示可以忽略 spec。修改者必须在同一变更报告中说明冲突、选择和修复结果，并同步更新对应架构文件或测试。

## 规范用语

- “必须/禁止”：发布级约束，修改时必须有报告、测试和明确结论。
- “应该”：默认设计选择；偏离时必须在报告中记录理由。
- “可以”：实现自由度，不构成兼容承诺。
- “已验证”：已有自动门控或记录在实施报告中的真实链路证据。
- “未承诺”：不能从当前实现或测试推导为产品能力。
