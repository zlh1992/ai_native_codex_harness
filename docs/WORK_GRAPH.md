# 多人 Work Graph 操作

老板在驾驶舱的员工管理中维护岗位、职责、能力标签、可用性与交付偏好。打开“我的工作台 → 任务首页”，选择自己的项目，输入目标，展开资料区选择候选员工与项目文本文件。

- **生成预览**：得到草稿，可增删任务、改负责人、依赖、清单、验收标准、成果路径与截止时间；整张图必须汇合至唯一最终交付节点。
- **EXECUTE · 生成并启动**：有效计划自动启动，将项目文件分享给涉及的员工，按依赖下发待办。规划对话不复制给员工。
- **审核方式**：人工、AI 建议后老板验收、自动验收与返工；最终交付可强制老板验收。首次实际业务建议先用 AI 建议评估质量。

老板图看板沿用黑绿任务首页，提供统计、依赖图缩放/滚动、选中关联节点、状态列表和事件记录。小屏默认列表。节点抽屉显示清单、审核意见和固定提交成果；下载/预览针对提交版本，之后修改员工文件不改变证据。

三个视图是同一份工作图的不同投影：**依赖图**按前后置关系排列任务，箭头表示必须先完成的依赖，适合看执行顺序与并行分支；**状态列表**不显示连线，集中展示负责人、当前状态、截止时间和阻塞原因，适合日常逐项检查；**事件记录**按时间倒序展示状态变化。依赖图和状态列表点击任务都会打开同一个详情抽屉。缩放只作用于依赖图；节点标题或任务数量较多时，可在卡片或看板内纵向滚动。

员工在任务首页打开“清单 / 交付”，完成清单，填写成果说明和项目内成果文件，提交验收。也可进入任务对话使用 Codex，选择本轮最终回复提交。打回会增加任务版本，显示修改要求；修正清单与成果后再次提交。通过才会汇入老板项目，后续员工获得已验收的上游 handoff 和文件基线。

## 等待与异常

| 状态 | 处理 |
| --- | --- |
| 等待前序 | 先完成依赖任务的验收 |
| 等待员工 | 同一员工先完成当前已下发任务 |
| 工作区忙 | 等当前对话结束；不要强制覆盖文件 |
| 输入树有修改或分叉 | 员工整理未交付工作，老板核对基线/冲突；系统保留原文件 |
| 需要老板验收 | 查阅审核意见、文件和独立验证证据，再通过或打回 |
| 权限/账号策略变化 | 恢复有效授权后，老板暂停并恢复图以更新运行授权；新 access 不会自动替换旧绑定，必要时取消后修订重启 |
| 模型结果不确定 | 打开老板自己的“工作图 · 规划/验收”对话核对；确认再次调用后，在后台任务卡重试 |
| 配额不足 | 在驾驶舱调整配额后重试；准备期间不会发布部分共享 |
| 合并冲突 | 保留 pending，先处理老板和员工文件冲突，再人工验收或重试 |

暂停会中断相关任务和后台调用，保留提交；恢复会使用新 generation。取消不撤销已经发布的项目访问权，不删除历史交付；需要撤权时用驾驶舱原有操作。已取消的未发布干净工作树自动清理，异常脏树保留。活动图不能在线改依赖；取消后保存新计划版本再启动。

自动审核有每图模型调用预算与返工次数上限。必需独立运行测试的任务请勾选“需要老板核对独立验证”，系统不会把模型阅读说明当成测试成功。二进制或超出读取预算的文件会转老板验收。

## 运维与回滚

环境开关默认 true，改动后在维护窗口重启 Portal 生效：

| 开关 | false 的效果 |
| --- | --- |
| `WORK_GRAPH_ENABLED` | 隐藏图入口并禁止新建/生成；既有历史读取接口保留 |
| `WORK_GRAPH_DISPATCH_ENABLED` | 不启动后台调度；既有业务数据保留，可人工处置 |
| `WORK_GRAPH_AUTO_REVIEW_ENABLED` | 阻止自动应用意见，转老板人工验收；AI 建议仍可生成 |

关闭页面不影响后台推进。调度每秒领取到期工作，30 秒补偿依赖及逾期检查；无变化不调用模型。Portal 重启后确定性业务步骤可重试，原生结果不确定则需要核对确认。维护 CLI 打开数据库不恢复活跃租约。

发布前在 macOS 上运行 `npm run gate`，验证 loopback 和 Seatbelt。按 [架构运维规范](../spec/architecture/08-operations-protocol-and-evolution.md) 绑定精确 `CODEX_BIN`，不要使用 App 自动更新后的不兼容版本。

回滚优先关闭派发与自动审核，暂停并排空全部图/turn，再停服备份完整 SQLite 与 workspaces/trees/trash。迁移包含 submission 表重建与 manual 身份约束；直接启动旧二进制可能破坏新记录。需要代码降级时，从同一停服时点的备份恢复旧代码与数据，或提供理解新 schema 的兼容版本。不要删除图表、手改 verdict 或清空提交来降级。包含工作图历史的项目和后台对话暂不支持普通删除，以保留证据。

第一版保持每项目一个活动图、每员工一个当前图任务、access 级工作树；多组织、自由画布、任意条件分支、独立测试执行器和即时聊天不在本版范围。
