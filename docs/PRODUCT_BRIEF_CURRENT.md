# Codex Harness Graph 产品说明书（实现对照补充）

本文把 2026-09-29 的 Graph 产品简述映射到当前代码能力，作为产品说明书的仓库内补充。长期约束仍以 [架构规格索引](../spec/architecture/index.md) 为准，运行和回滚以 [工作图操作说明](WORK_GRAPH.md) 为准。

## 产品闭环

老板在自己的 standard 项目中输入目标，选择候选员工和项目资料，生成一份可编辑的工作图草稿。老板可以调整任务标题、负责人、依赖、清单、必交成果、截止时间、独立验证要求和每个节点的审核方式。工作图必须无环，并汇合到唯一最终交付节点。

启动后，系统按依赖为员工准备独立 project access 和 Git worktree。自动分享只共享项目文件，不复制老板的规划对话。员工在任务首页查看清单和已验收的上游 handoff，也可以进入任务对话使用 Codex；前序任务未通过验收时，后续任务不会下发。

员工可以提交人工说明、文件或本轮已完成的 Codex 最终回复。提交会固定 Git commit/tree、清单快照、说明和附件清单；老板看到的是提交当时的证据。通过的提交先合入老板项目，再作为固定 handoff 交给后续任务；打回会生成新的任务版本并保留旧提交和审核记录。

审核支持三种策略：

- **老板人工审核**：不创建 AI 审核任务，提交后等待老板逐项通过或打回。
- **老板审核 · AI 提供意见**：AI 读取固定成果并给出逐项意见，老板决定结果。
- **AI 自动审核**：只有证据完整、策略允许且不需要独立验证时，AI 才能自动通过或打回；其他情况转老板处理。

最终节点可以继承默认策略，也可以单独要求老板确认。审核意见必须覆盖任务清单，AI 通过意见必须引用实际读取的固定成果；阅读 PDF 文本层或 DOCX 正文不能替代版式、图片或程序运行验证。

## 入口与视图

- 老板从 `/boss/login` 进入驾驶舱，再从“我的工作台 → 任务首页”创建和管理工作图。
- 员工从 `/employee` 进入任务首页，只看到自己的任务和当前有效授权项目。
- 老板可在任务看板、依赖图、状态列表和事件记录间切换；四种投影都打开同一份任务详情。员工看板可按工作图筛选，并保留返工、提交和已通过的历史状态。

## 与 Graph 主说明的关系

Graph 只运行在 standard 项目。local_private 项目永不分享、不创建工作图，并使用老板本机回环 Qwen；微信入口只是固定到老板 standard `weichat-project` 的 transport relay，不能成为员工项目或隐私项目的入口。管理员维护账号、资料、配额和授权，但不能因 admin 角色直接读取员工私有项目内容。

当前系统仍是内部互信试用：所有普通项目共享本机 Codex 登录和额度，公网访问经过 HTTPS 隧道；系统不承诺敌对租户级隔离、独立上游账号、自动冲突解决或独立测试执行器。
