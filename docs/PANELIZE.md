# 老板多模型会审

在老板自己的普通项目对话中使用 EXECUTE 模式并开启联网，输入：

> 使用 $panelize-multi-agent，让 Codex、Kimi、豆包、DeepSeek 并行分析：这里写问题。

微信绑定的老板对话也支持同一指令。Codex 为当前对话模型；Claude Code / MiniMax 暂未配置，会明确跳过，不使用本机其他 Claude provider。

Agent 打开三个供应商标签，先填入并核对，再各发送一次；网页生成期间 Codex 独立分析。最终回复区分各家的实际答案、来源、分歧以及未登录/未完成者，不将发送尝试标成完成。

需要登录时，在同一对话的工作台浏览器抽屉点击「开始接管」，登录后「操作完成，交还 Agent」。微信无法直接操作抽屉；等待登录时会收到一次本对话工作台链接，需打开对应老板工作台对话；不要把密码、验证码发到聊天里。浏览器独立于日常 Chrome，运行结束删除临时登录态，下轮可能需要重新登录。

不支持员工、隐私项目、共享给老板的项目或任务/工作流对话。已有草稿不会覆盖，不确定发送不会自动重试。旧对话首次使用会升级模型线程并保留页面历史，旧资料不会自动外发；需要旧资料时请明确指定。

本集成只复用 Panelize 固定适配器，使用 Portal 标签页和接管界面，不另装完整扩展。技术边界见 [架构说明](../spec/architecture/13-panelize.md)。
